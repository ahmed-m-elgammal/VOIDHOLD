# T0.5 — Adaptive UI/UX Wireframes Landscape + Portrait (Docs only)

Owner: UI/UX designer. Reviewers: Designer + engineer + QA.
Inputs: T0.2 loop + warnings list. Game: `VOIDHOLD: Moon Colony` (`com.voidhold.colony`). Locales v1: `en` + `ar` only (`es`/`de` stubbed later).
Output: Figma wireframes + interaction spec in en + ar, RTLmirrored.

## 1. Screens (12 minimum, each in BOTH orientations)
1. Splash + loading + disclaimer
2. Main menu (Continue / New / moons / settings / About)
3. HUD default (TopHud + BuildBar closed/open)
4. BuildBar Service / Industry / Colonists cards with cost + lock state
5. Placement ghost (valid/invalid + radius + entrance arrow + rotate)
6. BuildingSheet (status, damage, efficiency, storage, workers slider, import/export, demolish)
7. UnitCard (portrait, happiness/fullness, job, carrying)
8. Dome status + warnings feed (`No energy`, `Output full`, `Starving`, `Under attack`)
9. Pause (Save&Exit, quality, music/sound/haptics, language)
10. Reports/graphs (storage/production/pop/damage)
11. Tutorial FTUE 7 steps overlay + first-fail coaching
12. Shop stub Locked state + settings legal (privacy/support) + restore placeholder

## 2. Interaction spec
- Touch targets >=48dp, safe-area + notch, gesture conflicts (draw vs pinch) resolved.
- Back hierarchy: sheet -> deselect -> pause. No hard quit on mobile back.
- Portrait: bottom drawer collapsible, full-screen sheets. Landscape: bottom bar + right inspector.
- Haptics + sounds per action (place/error/select/warning). Dark text on bright snow readability pass.
- Accessibility: color-blind safe resource colors + icons + labels, font scaling, reduced-motion option.

## 3. DB / data hooks
- `strings_en.csv` + `strings_ar.csv` keys for all labels (no hard-coded English). `strings_es.csv`/`strings_de.csv` stubbed empty for later.
- Arabic RTL mirroring + font fallback + number formatting per `mobile/localization-en-ar.md`. Full FTUE run in ar required.
- Define warning event list for analytics: `warning_shown/dismissed`, `ftue_step_completed`, `placement_failed_reason`.

## 4. Best practices
- One primary action per sheet. Demolish requires confirm (destructive, 2-tap).
- Always show WHY: efficiency breakdown (oxygen/damage/mood), not just a bar.
- Tablet-first layout must collapse cleanly to 6" phone without horizontal scroll.
- Test on sunlight brightness: contrast ratios logged.
